# 从 Figma 生成页面

你将根据 Figma 页面/Frame URL 生成完整的前端页面。

## 核心原则

目标是页面在浏览器中的视觉效果与设计稿一致。用最简洁的代码结构实现相同视觉效果。
页面生成必须默认组件化：页面文件负责编排，具体 UI 单元由已有或新建组件承载。

## 第一步：检测项目技术栈

1. `package.json` → 框架、样式方案、路由库
2. `tsconfig.json` → 语言、路径别名
3. 扫描项目结构 → 页面目录、组件目录、路由方式
4. 读取已有页面 → 匹配写法模式

## 第二步：获取 Figma 设计数据

1. 调用 `get_node({ url, depth: 10, precision: "implementation" })` 获取页面完整视觉结构
2. 调用 `get_node_css({ url, recursive: true, mode: "css", depth: 10 })` 获取样式参考
3. 如有引用组件或组件集，调用 `get_component_variants({ url })` 或传入对应组件集节点
4. 如有图标/矢量/图片且代码需要真实资源，调用 `export_image({ url, format: "auto" })` 或传入明确 `nodeIds`；明确必须 SVG 时调用 `export_svg`
5. 如果 URL 缺少 `node-id`，先调用 `get_file_structure({ url })`，再用 `search_nodes({ url, parentId/pageId, type: "FRAME" })` 定位页面 frame

## 第三步：盘点已有组件

扫描项目组件目录，将设计中的 UI 单元与已有组件匹配：

- 直接复用 → import 使用
- 扩展复用 → 修改已有组件
- 新建 → 才生成新组件

## 第四步：分析复杂度

### 默认生成策略

1. 先制定组件拆分计划
2. 先实现或扩展组件
3. 再生成页面文件并引用组件
4. 完成前执行组件化自检

简单页面也要拆分有明确工程边界的区块或复用单元；复杂页面可以先实现完整视觉骨架，再立即拆分组件并重构引用。

### 组件拆分计划

生成代码前列出：

- 页面壳与路由/布局编排职责
- 可直接复用的已有组件
- 需要扩展复用的已有组件
- 必须新建的页面区块组件、共享组件和复用 UI 单元
- 组件的 Props、事件和数据输入边界

### 组件拆分标准

- 必须提取：Figma COMPONENT / COMPONENT_SET、明显复用单元、重复 2 次以上的卡片/列表项/按钮组/导航项/表单项
- 必须提取：有独立交互、局部状态或事件接口的区域，例如 tab、dropdown、modal、form、carousel
- 必须提取：有独立数据输入边界的区块，例如 user card、product card、sidebar item、metric tile
- 可以内联：一次性、无交互、无复用价值的纯布局 wrapper 或细小装饰元素
- 不复刻 Figma 的无意义嵌套 frame；按工程语义和目标项目约定拆分

## 第五步：生成代码

- 页面放到项目约定的页面目录
- 引用已有/新建的组件
- 预留事件接口（导航、数据加载、表单提交）
- 响应式布局遵循设计稿断点（如有）
- 页面文件主要负责路由、布局编排和数据传入
- 组件文件负责自身结构、Props、样式和局部状态接口

## 第六步：组件化自检

完成前必须检查：

- 页面文件没有承载大量重复 DOM
- 重复 UI、独立交互区块、独立数据区块已提取或复用组件
- 组件目录、命名、导出、样式和 Props 模式符合目标项目约定
- 不存在只为复刻 Figma 嵌套结构而创建的无意义组件

## 第七步：验证

构建通过 + dev server 中视觉效果正确。
